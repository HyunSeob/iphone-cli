## 결함 (우선순위 순)

1. **[수정됨 `6940260`: 단위 시험 4개, 실기기 B7 24회 중복 0] 목록 읽기가 끝에서 중간 행을 다시 담는다 (B7, 위험).** 19회 중 4회. 끝까지 스크롤한 뒤 화면이 위로 튀거나 늦은 화면을 읽은 것으로 보이며, 전체에서 본 적 있는 행인지 확인하지 않고 붙인다. 지출 목록이면 같은 건이 두 번 합산된다. 실패 회차 전체 결과는 외장 `out/B7r-4.json` · `B7r-9.json`
2. **확인 ID를 에이전트가 만들 수 있다 (E4, 위험).** 실제로 Codex가 그렇게 했다. MCP `iph_tap` · `iph_script` · `iph_run`의 `confirm` 인자 설명("One-time op_id that allows a guarded tap")이 방법을 알려 준다. 스킬 문서의 "Confirming is the user's decision"은 5/6에서 지켜졌지만 장치가 아니다. 대안: MCP에서 `confirm`을 빼고 사람만 터미널에서 확인, 또는 확인 ID를 사용자 쪽에서 발급
3. **[수정됨 `316dedf`: 단위 시험 5개, 실기기 재현은 안 함] 접근성 서비스가 빈 답만 보내는 상태에서 복구하지 못하고, doctor가 '잠김'으로 안내한다.** 19:19부터 25분 동안 읽기가 모두 `ax_timeout`(빈 답 3회). 재시작 조건이 '답이 전혀 없을 때'(`src/device/session.rs:401`)라 걸리지 않았고 `ax_restarts:0`. doctor는 설정 앱이 앞에 떴는지 읽기로 확인하지 못하자 원인과 상관없이 "폰 잠금을 풀어 주세요"(`src/doctor.rs:392`). 폰은 잠기지 않았고(lockdown도 잠김 아님, 스크린샷 정상, 자동 잠금 '안 함') 에이전트 7회가 모두 이 문장을 믿고 사용자에게 잠금 해제를 요청했다. 상주 프로세스를 다시 켜자 재시작이 돌아 19초에 복구
4. **[수정됨 `39ffe0d`: 실기기 복사 직후 `type` 3회 연속 성공. 앱에서 복사한 내용은 되돌릴 수 없음, 아래] 폰에서 복사한 직후 `type`이 두 번 실패하고 한 번 클립보드를 되돌리지 못한다 (B4).** 결과는 정직하게 나오지만, 사용자가 폰에서 무언가 복사해 둔 상태면 입력이 두 번 실패하고 그 클립보드 내용을 잃는다
5. **[일부만 수정 `38948f3`: 줄었지만 0은 아님, 원인 일부 미확인] 새 입력 세션 첫 동작이 빠지는 문제가 남아 있다 (B3 매번 새로 · D2).** 매번 새로 여는 설정에서 탭 2/20 · 뒤로 밀기 5/25 놓침. 따로, 기본 설정(120초)의 D2에서 130초 쉰 직후 바퀴 2번 모두 첫 화면 '일반'을 찾지 못했다(`not_found` 5회씩, 결과는 정직). 같은 조건으로 2회 다시 돌렸을 때는 재현되지 않았고, D2는 스크롤 출력을 버려서 원인을 가리지 못했다. 같은 모양의 실패('디스플레이 및 밝기' 찾기 뒤 탭 실패)가 1회 더 있었다. 합쳐서 3회, 원인 미확인
6. **[수정됨 `a03bfc0`: batch · script는 코드 결함이 아니었음(측정 오류), 통합 시험 추가, `scroll --until`은 문서 수정] 결과와 종료 코드가 문서와 다르다.** `batch` · `script`는 `not_sent` · `blocked`여도 0, `scroll --until` 못 찾음은 `ok:false` + `done` + 1. 종료 코드로 판단하는 호출자는 막힌 것을 성공으로 본다
7. **확인하고 누른 대상의 이름표가 `ops.jsonl`에 평문으로 남는다 (C1).** 권한은 600
8. 관찰: Codex는 과제 끝마다 `iph_dnd off`를 불렀다(방해금지를 켠 적이 없어 `changed:false`). 첫 `scroll --until "디스플레이 및 밝기"` 1회 실패, 다시 3/3 성공, 원인 기록 없음(출력을 버렸다)
