FAQ

Common questions

How can Claude Code or Codex control a real iPhone without Xcode or WebDriverAgent?
Install iph, plug in your iOS 27+ iPhone, run iph setup, and register the MCP server via claude mcp add iph -- iph mcp or codex mcp add iph -- iph mcp. You can also link skills/iph so the agent uses iph directly from the shell.
Why use the accessibility tree instead of screenshots and OCR?
The native accessibility tree returns structured roles, labels, values, enabled states, and frames in compact JSON. Agents use a fraction of the tokens required for repeated screenshots and target controls semantically (iph tap "General", role=button label~="Save") rather than brittle pixel coordinates.
Does iphone-cli work on Windows or in the EU without macOS iPhone Mirroring?
Yes. iph talks directly to the phone's developer services over USB or LAN/Wi-Fi. It runs natively on both macOS and Windows 10/11 (x64) and is completely unaffected by EU iPhone Mirroring restrictions.
Which iOS versions and devices are supported?
Real physical iPhones running iOS 27 or later over USB or the same LAN/Wi-Fi. Touch and keyboard input rely on com.apple.coredevice.displayservice introduced in iOS 27. iOS Simulators, Android devices, Linux hosts, and landscape orientation are currently out of scope.
How does iphone-cli prevent accidental double taps or duplicate orders?
Because iOS never confirms HID touch packets, every command returns outcome (done, not_sent, or unknown) alongside sent, verified, and screen_changed. An unknown outcome exits with code 2 and halts scripts immediately so agents inspect the screen before resending input.
