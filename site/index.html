Let AI agents read and operate any app on a real physical iPhone through the native accessibility tree — straight from your terminal. No Xcode. No WebDriverAgent. No app installed on the phone.

Why iphone-cli

Accessibility Tree, Not OCR

Reads structured UI elements (role, label, value, frame, identifier) directly from Apple's remote accessibility service. Targets elements by label or selector instead of brittle coordinates.

No Xcode or WebDriverAgent

Talks directly to Apple's developer services over USB or Wi-Fi. No code signing, no XCUITest runner, no Appium server, and no app installed on the iPhone.

Built-in QuickJS Scripting

Run loops, conditionals, list extraction (readList), and multi-step flows in a single agent call via an embedded QuickJS engine (iph script / iph run).

Agent-Ready & Safety-First

Ships with an MCP server (iph mcp), Agent Skill (SKILL.md), and strict outcomes (done / not_sent / unknown) to prevent double taps or duplicate orders.

Quick Install

Single native binary — no Python, Node.js, Xcode, or Rust runtime required.

# macOS (Apple Silicon & Intel universal binary)
curl -fsSL https://raw.githubusercontent.com/HyunSeob/iphone-cli/main/install.sh | sh
iph setup

# Or via Cargo (Rust 1.88+, macOS & Windows)
cargo install iphone-cli

On Windows 10/11 (x64), download iph-windows-x86_64.zip from GitHub Releases and install Apple's device service via the Microsoft Store (Apple Devices) or winget install Apple.AppleMobileDeviceSupport.

Connect to Claude Code or Codex

# Register the built-in MCP server
claude mcp add iph -- iph mcp
codex mcp add iph -- iph mcp

# Example terminal workflow
iph read --human
iph tap "General"
iph type "hello" --submit

Architecture

iph (CLI) ─┐
iph mcp  ──┼─ Unix socket / named pipe ─ iph daemon ─ lockdown → CoreDeviceProxy → TCP tunnel → RSD
           ┘                              ├ axAuditDaemon.remoteAXService   (accessibility tree)
                                          ├ displayservice + universalhid   (touch, keyboard)
                                          ├ pasteboardservice               (clipboard)
                                          ├ appservice                      (launch, app list)
                                          └ screencaptureservice            (PNG capture)

Built in Rust on top of idevice (MIT) and jktcp (MIT), inspired by the documented principles of Poki.

Frequently Asked Questions

How can Claude Code or Codex control a real iPhone without Xcode or WebDriverAgent?

Install iph, connect your iOS 27+ iPhone over USB, run iph setup, and add the MCP server via claude mcp add iph -- iph mcp or codex mcp add iph -- iph mcp. You can also link skills/iph so the agent uses iph directly in the shell.

Why use the accessibility tree instead of screenshots and OCR?

The accessibility tree exposes exact UI roles, labels, values, and frames in compact JSON. Agents spend far fewer tokens than sending screenshots every turn and target controls semantically (iph tap "General", role=button label~="Save") instead of stale coordinates.

Does iphone-cli work on Windows or in the EU without macOS iPhone Mirroring?

Yes. iph connects directly to the iPhone's developer services over USB or Wi-Fi, so it runs natively on both macOS and Windows 10/11 (x64) and does not depend on macOS iPhone Mirroring.

Which iOS versions and devices are supported?

Real physical iPhones running iOS 27 or later over USB or the same LAN/Wi-Fi. Touch and text input rely on com.apple.coredevice.displayservice, introduced in iOS 27. Simulators, Android, Linux hosts, and landscape mode are currently out of scope.

How does iphone-cli prevent accidental double taps or duplicate actions?

Because iOS does not acknowledge HID touch packets, every command returns structured JSON with outcome (done, not_sent, or unknown), sent, verified, and screen_changed. An unknown outcome exits with code 2 and halts scripts so agents read the screen before retrying.
